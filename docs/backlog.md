# Backlog

Prioritized list of planned features, improvements, and technical debt for **`prowl-review`** — a BYOK (bring-your-own-key) AI code-review tool for the Prowl QA suite. Delivered first as a GitHub Action + local CLI in TypeScript, reusing `prowl`'s toolchain and the provider abstraction from `prowl/src/generator/ai.ts`. Multi-provider (Claude default / OpenAI / Gemini). Apache-2.0.

**Positioning (why we're building, not just tuning Claude Code's review):** a single-pass, diff-only LLM review (what Claude Code and Codex do today) misses the bugs that live in the seam between changed code and its callers, and it *reads* like a wall of text. The paid tools (CodeRabbit, Greptile, Qodo) win on four techniques + presentation, all replicable BYOK: (1) **cross-file context** via **agentic retrieval** (grep/read on demand — NOT a vector DB), (2) **multi-pass specialized review + a judge/dedup pass**, (3) **linter/SAST grounding**, (4) **false-positive verification**; plus a **structured walkthrough + committable inline suggestions**. Cost is managed via **prompt caching** + **risk-tiered** agent counts, so per-review stays in cents — still far under CodeRabbit's ~$576/yr for this user.

User stories use **As a `<role>`, I want `<capability>`, so that `<value>`.** Each carries acceptance criteria.

45. **Codex-CLI subscription provider (`provider: codex`) — un-parked 2026-08-24** *(reopened from resolved.md "Deferred / parked")*
    As a solo maintainer on a ChatGPT Pro plan, I want prowl-review to run its reviews through my Codex subscription instead of a metered API key, so that per-review cost drops to zero marginal and I can retire CodeRabbit without a second bill.
    - **Why it was blocked (2026-07-01):** the assumed mechanism was calling OpenAI's Codex backend directly with subscription OAuth tokens — reverse-engineered, tolerated-but-not-sanctioned. **Why it is un-blocked (owner decision, 2026-08-24):** the mechanism is now OpenAI's **first-party** surface — the official `codex` CLI (`codex exec`, documented non-interactive mode with `--output-schema`/`--json`) and/or `@openai/codex-sdk`, signed in with ChatGPT. OpenAI's pricing page states CLI/SDK usage under ChatGPT sign-in draws from the plan allowance; OpenAI publicly endorses subscription use in third-party harnesses (2026-05). The recorded residual: OpenAI *prefers* API keys for automation and its CI/CD-auth guide says **"Do not use this workflow for public or open-source repositories"** on shared/hosted CI — so this provider is supported only on infrastructure the user controls (see #64), never via `auth.json` in GitHub secrets. Owner context: the Prowl GitHub account has no OpenAI access, so the subscription must live on the runner, not in repo secrets.
    - **Mechanism:** a new `src/providers/codex.ts` implementing `Provider` (`src/providers/types.ts`), registered in `src/providers/index.ts`; `codex` added to `PROVIDER_NAMES`/`DEFAULT_MODELS`. Inference = spawn the official `codex` binary (never the backend OAuth endpoints): `codex exec --ephemeral --ignore-user-config --sandbox read-only -C <scratch dir> --skip-git-repo-check -m <model> -c model_reasoning_effort=<effort> --json --output-schema <schema>` with **stdin closed** (a non-TTY stdin makes `codex exec` block on "Reading additional input from stdin"); take the **last** `agent_message` (Codex can emit a premature message before its tool call); map `turn.completed.usage` (`input_tokens`/`cached_input_tokens`/`cache_write_input_tokens`/`output_tokens`) → `TokenUsage`. JSON results need an object root, so wrap the findings array (same wrinkle `openai.ts` documents). Auth comes from `CODEX_HOME` (ChatGPT sign-in); `resolveProviderConfig` must allow a **keyless** `codex` config instead of requiring `PROWL_AI_KEY*`. Missing/unauthenticated `codex` binary → clear error naming the fix (`codex login` on the runner).
    - **Agentic retrieval:** `completeWithTools` has no 1:1 mapping (Codex runs its own tool loop). Implement via the `deps.gatherContext` seam in `src/pipeline.ts`: one `codex exec --sandbox read-only -C <repo>` that returns the context bundle by schema, then run the bundle through the existing redaction (`src/review/redact.ts`) and sensitive-file rules, because Codex's shell bypasses `src/context/tools.ts` confinement. Retrieval bounds (`maxFiles`/`maxRounds`/budget) still honored and still reported when hit (no silent truncation). Works as an ensemble member (#53) alongside API-key providers.
    - **Models:** default `gpt-5.5`; failback ladder `gpt-5.6-terra → gpt-5.5`. `gpt-5.4`/`gpt-5.4-mini` leave ChatGPT sign-in on **2026-08-31** and must not be defaults here. Reasoning effort configurable (`low` for specialists, `medium`+ for judge/verification).
    - **Policy surface (must ship with the code):** OpenAI/Codex only — **no Claude/Gemini equivalent, ever** (their consumer terms prohibit it); off by default; opt-in via `provider: codex` / `PROWL_AI_PROVIDER=codex`; documented as "self-hosted / local infrastructure only — not for GitHub-hosted runners on public repos". Rewrite the "Why API keys only — the subscription question" section of `docs/auth.md` (+ `README.md`, `docs/privacy.md`) to the new stance and update `test/docs-auth-privacy.test.ts` accordingly; update `prowl-code-review-docs` (review.prowl.tools) and the `prowl-web` provider list; `CHANGELOG.md` entry.
    - Acceptance: `provider: codex` produces a full review (walkthrough + inline findings + check run) end-to-end on a real PR with no `PROWL_AI_KEY*` set; unit tests cover spawn args, stdin handling, last-message selection, schema wrapping, usage mapping, keyless config, missing-binary/unauthenticated errors, and redaction of the retrieval bundle; the provider is removable by deleting one file + registry entry; docs/test/stance updates above land in the same change; `npm run build`/`lint`/`test` green.

64. **Self-hosted runner rollout — prowl-review on Lucius' Mac mini (subscription-backed reviews for all Prowl repos)**
    As the owner, I want every Prowl repo's automatic + `@prowl-review` reviews to run on the always-on Mac mini I already use for runners, using the Codex subscription login that lives only on that machine, so that reviews are hands-off, zero-marginal-cost, and no subscription credential ever enters GitHub.
    - **Runner:** org-level self-hosted runner on the Mac mini, in a runner group restricted to the prowl-review workflows, labels e.g. `[self-hosted, macOS, prowl-review]`. A **dedicated `CODEX_HOME`** for the runner with its own one-time `codex login` (ChatGPT sign-in) — **never** copy `auth.json` from another machine (refresh tokens are single-use; a copied file logs out whichever side refreshes second). Pinned `codex` CLI version + `prowl-review` version on the runner; a documented "re-login" runbook for when the session is revoked.
    - **Workflow changes (`.github/workflows/prowl-review.yml` + `prowl-review-command.yml`, then `examples/workflows/` + `examples/reusable/` templates):** `runs-on` the runner labels; a **job-level `if:`** same-repo gate so fork PRs are never scheduled onto the self-hosted runner (today's step-level gate is not enough — the job must not land there at all); a `concurrency` group per runner so Codex runs are serialized (one `auth.json` = one serialized stream, per OpenAI's guidance; specialist fan-out inside a single run is fine); `ai-provider: codex` and **no** `PROWL_AI_KEY_*` secrets on that job; keep the branded `prowl-review[bot]` App token for posting so the ChatGPT login never appears on GitHub (anonymity policy).
    - **Accepted risk, recorded:** GitHub advises against self-hosted runners on public repos because any PR can run code on them. Mitigations: the job-level same-repo gate means only the owner's own accounts/agents can trigger a run; Codex runs `--sandbox read-only`; grounding linters (ESLint config is executable) run only on same-repo PRs; runner group limited to these workflows; runner user is unprivileged with no access to other secrets on the machine. Revisit if any Prowl repo ever accepts outside contributors' PRs onto this path (then route those to the GitHub-hosted API-key ensemble instead).
    - **Rollout:** `prowl-code-review` first (dogfood, prove #45 + #65 end-to-end), then `prowl`, `prowl-hub`, `prowl-infra-hub`, `prowl-web`, `prowl-docs`, `prowl-code-review-docs`. Decide per repo whether the GitHub-hosted Claude+Gemini ensemble stays (as a public-safe fallback) or is retired to stop the API spend. CodeRabbit is removed from each repo once its prowl-review run is green.
    - Acceptance: a same-repo PR on each listed repo gets a review posted from the Mac mini runner with no provider secret in that repo; a fork PR never schedules on the runner (verified with a throwaway fork); a runner restart/re-login runbook exists (secrets-bearing details in the private runbook, public docs hold the shape only); the example workflows/docs show the self-hosted + `codex` pattern with the public-repo caveat stated verbatim.

65. **Subscription usage-limit resilience & zero-cost reporting (for `provider: codex`)**
    As a maintainer on a metered-by-window subscription, I want prowl-review to degrade gracefully when the 5-hour / weekly Codex allowance is exhausted, so that a burst of agent-generated PRs never produces red checks or half-reviews.
    - Detect Codex usage-limit / 429 outcomes distinctly from transient errors: transient → existing retry/backoff; limit reached → **neutral** check run + a review note ("skipped: Codex subscription usage limit; retry with `@prowl-review review` after <reset>"), never a failure, never a partial review presented as complete. Parse the reset hint from Codex output when available.
    - Cost line reports **`$0.00 (ChatGPT subscription)`** while still showing input/cached/output tokens; per-PR budget cap (#18-style `maxTokens`) keeps working as a token cap even though price is zero; ensemble runs mixing `codex` with API-key providers price each member correctly.
    - Model-retirement safety: when a configured model is no longer offered under ChatGPT sign-in (as with `gpt-5.4` on 2026-08-31), fail over via the failback ladder and say so in the review notes.
    - Acceptance: tests for limit-vs-transient classification, neutral-check + note rendering, zero-cost pricing with token counts, mixed-ensemble pricing, and retired-model failover; the `@prowl-review review` re-run path works after a limit skip.
